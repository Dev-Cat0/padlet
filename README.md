# Padlet Sender 웹 패널

실제 브라우저에서 성공한 게시 요청을 캡처하고 **같은 브라우저 페이지와 세션**에서 전송합니다. 성공한 요청의 게시판·작성자·입력 항목을 보존하며, 쿠키를 별도 HTTP 클라이언트로 복사하지 않습니다. 공식 Padlet API 키는 사용하지 않습니다.

- 웹 패널: https://dev-cat0.github.io/padlet/
- 서버: https://padlet-sender-panel.onrender.com
- Render 관리: https://dashboard.render.com/web/srv-dbae7t0m7kps738gj5c0

## 사용 방법

1. 웹 패널에서 게시판 주소를 입력하고 **게시판 브라우저 열기**를 누릅니다.
2. 아래 브라우저 화면을 클릭해 필요한 보안 확인을 직접 마치고 **글을 1건 게시**합니다. 한글·비밀번호는 화면의 입력란을 클릭한 뒤 별도의 텍스트 입력란으로 전달합니다. 이 글은 실제 게시물로 남으며 반복 전송 횟수에는 포함되지 않습니다.
3. 성공한 게시 응답이 확인되면 게시판 이름·섹션·입력 항목을 조회하고 **성공 요청 캡처됨**으로 표시합니다. 게시한 글의 값을 전송 설정에 불러옵니다. 제목·본문·첨부 링크·지원하는 추가 항목을 수정할 수 있습니다.
4. 횟수·주기를 설정하고 **전송 시작**을 누릅니다. 매 주기마다 모든 섹션에 각각 1건씩 게시합니다. 섹션 3개 × 10회는 총 30건입니다. 기본값은 섹션당 50회 / 0.3초이며, 0회는 무제한입니다. 섹션이 없으면 매 주기 1건입니다.
5. **중지**는 진행 중인 요청의 결과를 받은 뒤 멈춥니다. **브라우저 세션 종료**는 작업을 멈추고 브라우저·쿠키·캡처 정보를 삭제합니다.

캡처가 끝나면 화면은 숨기고 브라우저는 유지합니다. 전송 중에는 브라우저 조작을 잠급니다. HTTP 401·403, 보안 확인, 게시 성공을 확인할 수 없는 응답은 중지하며 브라우저에서 상태를 확인하고 다시 캡처해야 합니다. CAPTCHA를 자동으로 해결하지 않습니다. 서버의 브라우저에서도 보안 확인이 계속되면 사용할 수 없습니다.

탭을 닫아도 서버 작업은 계속될 수 있으므로 먼저 중지하세요. 같은 탭 새로고침은 상태를 복구하지만 탭을 닫아 세션 식별자가 사라지면 다시 접근하지 못할 수 있습니다. 서버 재시작·재배포 시 모든 세션과 작업은 사라집니다. 전송·브라우저 조작 없이 30분이 지나면 연결을 정리합니다. 무료 서버의 메모리를 고려해 브라우저는 서버 전체에서 한 세션만 사용합니다.

## 전송 동작

- 성공한 POST `/api/9/wishes`의 JSON을 복사합니다. 변경하지 않은 본문의 HTML과 패널에서 편집할 수 없는 추가 항목은 보존합니다. 수정한 본문은 HTML 이스케이프하며 줄바꿈을 보존합니다.
- 새로운 게시물의 `cid`와 작성·수정 시각을 생성하고, 대상 섹션 ID를 설정합니다. 게시판별 필수 항목을 전송 전에 검증합니다.
- 전송은 캡처한 페이지의 `fetch`로 실행합니다. 쿠키·CSRF는 브라우저 안에서 사용하고 상태 API로 내보내지 않습니다. 다른 출처로 전송하거나 게시 요청의 리디렉션을 따라가지 않습니다. 페이지가 바뀌면 다시 캡처해야 합니다.
- 한 묶음은 최대 8개 요청을 동시에 처리하며 다음 묶음과 겹치지 않습니다. 응답 시간은 주기에 포함하고 임의 지연을 추가하지 않습니다. 실제 간격은 응답·요청 제한으로 길어질 수 있습니다.
- 429는 3초씩 증가하는 대기(최대 30초)와 더 긴 숫자형 `Retry-After`를 따릅니다. 같은 주기에서 이미 성공한 섹션에는 다시 보내지 않습니다. 다른 HTTP 오류·타임아웃은 자동 재전송하지 않습니다.
- HTTP 422는 Padlet의 게시 요청 거부입니다. 인증 정보를 가린 오류 사유를 표시하고 중지합니다.
- 추가 항목은 텍스트·숫자·날짜·이메일·URL·전화번호·단일 선택을 편집할 수 있습니다. 그 밖의 항목은 처음 게시한 값을 유지합니다. 파일 업로드·녹화는 브라우저의 Padlet 화면에서 합니다.
- 섹션과 입력 항목은 캡처 시 조회합니다. 게시판 설정·섹션 변경 후에는 다시 캡처하세요. 비공개 웹 요청 형식이 바뀌거나 접근이 제한되면 동작하지 않을 수 있습니다.

## 구성과 배포

- `web/`: GitHub Pages 정적 웹 패널. `web/config.js`의 Render 주소에 연결합니다.
- `server/browser.py`: 수동 브라우저 조작, 성공 요청 관찰, 같은 페이지의 전송.
- `server/engine.py`: 캡처한 게시판 확인과 전송·중지 루프.
- `server/fields.py`: 게시판별 기본·사용자 지정 항목 조회와 검증.
- `server/errors.py`: 인증 정보를 가린 오류 메시지.
- `server/anonymous.py`: URL·게시판 조회 도우미와 이전 GET 전용 초기화. 공개 연결 API는 브라우저 캡처를 사용합니다.
- `server/sessions.py`: 사용자별 메모리 세션과 만료, 단일 브라우저 사용 제한.
- `desktop/padlet.py`: 전달받은 원본 보존용.
- `Dockerfile`: Playwright Python 1.58.0 이미지와 같은 버전의 패키지, `pwuser` 실행.

GitHub Pages Source는 **GitHub Actions**입니다. `main`의 `web/` 변경 시 `.github/workflows/pages.yml`이 배포합니다. Render는 기존 `padlet-sender-panel` 무료 Docker 서비스를 사용합니다. `render.yaml`은 대체 Blueprint용이므로 중복 서비스를 만들지 않습니다.

Render 설정: `main`, Dockerfile `./Dockerfile`, Singapore, Free, `ALLOWED_ORIGINS=https://dev-cat0.github.io`. 상태 확인 경로는 `/healthz`입니다. 서버 상태가 메모리에 있으므로 Uvicorn worker와 Render 인스턴스는 각각 하나로 유지합니다.

브라우저 네트워크는 허용된 Padlet·인증·보안 확인 관련 도메인의 공개 주소로 제한합니다. 내부 주소, 기타 도메인, 다운로드는 허용하지 않습니다. 세션 생성은 분당 20회, 총 32개로 제한합니다. 공개 자동 연결이므로 사용자 계정 인증을 제공하는 것은 아닙니다.

## 개발 및 검증

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m playwright install chromium
$env:ALLOWED_ORIGINS = 'http://127.0.0.1:4173'
.\.venv\Scripts\python -m uvicorn server.app:app --host 127.0.0.1 --port 4174 --no-access-log
```

별도 터미널에서 `python -m http.server 4173 --bind 127.0.0.1 --directory web`을 실행합니다. 로컬 검증 때만 `web/config.js`의 주소를 `http://127.0.0.1:4174`로 바꾸고 배포 전에 되돌립니다.

```powershell
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python tests/browser_smoke.py
node --check web/app.js
```

단위 테스트는 캡처 검증·게시판 일치·인증·세션 분리·필수 항목 보존·섹션 전송·중지·429 처리를 확인합니다. 브라우저 통합 검증은 모든 네트워크 요청을 모의 응답으로 처리하며, 실제 Chromium에서 수동 게시 캡처 → 같은 쿠키·페이지로 전송 → 403 중지 → 세션 정리를 확인합니다. 실제 게시판에는 테스트 글을 올리지 않습니다.
