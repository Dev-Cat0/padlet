# 로컬 디스코드 키 봇

키 발급과 키 기록은 관리자 PC의 봇·SQLite에서 관리합니다. **웹 키 입력 → 자체 백엔드 검증 → 임의 세션 토큰 발급** 순서로 접속합니다. 백엔드는 로컬 봇과 인증된 WSS 연결로 키의 유효성을 확인하고, 웹에는 별도로 생성한 임의 세션 토큰만 응답합니다. 이후 실행·상태·중지 요청에는 세션 토큰만 사용합니다.

원본 키는 웹 저장소나 로그에 저장하지 않으며 입력란은 요청 직후 비웁니다. 로컬 DB에는 HMAC만 저장합니다. **최초 로그인 요청의 키는 본인의 개발자 도구 Network에서 볼 수 있습니다.** 웹에서 직접 입력하는 키를 사용자 자신의 개발자 도구에서 숨기는 것은 불가능합니다. 다른 사람의 키 목록이나 관리자 발급 권한은 웹에 전달하지 않습니다.

현재 웹사이트와 API가 서로 다른 사이트(GitHub Pages/Render)에 있어 타사 쿠키 제한의 영향을 피하도록 임의 Bearer 세션을 `sessionStorage`에 저장합니다. HttpOnly 쿠키 방식은 아니며, 브라우저에서는 키 대신 이 세션 토큰을 확인할 수 있습니다. 토큰 자체도 접속 자격 정보이므로 공유하지 마세요.

## 최초 실행

1. 대화에 노출된 봇 토큰은 [Discord Developer Portal](https://discord.com/developers/applications)의 **Bot → Reset Token**에서 재발급합니다. 기존 토큰은 이 프로젝트에 저장하지 않았습니다.
2. Python 3.11 이상이 설치된 PC에서 프로젝트 폴더의 `start-keybot.ps1`을 실행합니다. 봇 전용 가상 환경에 필요한 패키지만 설치합니다. 설정 화면에서 **새 토큰**과 **Discord 서버 ID**를 입력합니다. 토큰 입력은 화면에 표시되지 않습니다.
3. 생성된 `.local/keybot/server-secret.txt`의 `KEY_AGENT_SECRET`을 **기존 패들렛 API 서버의 환경 변수**로 직접 등록합니다. 로컬 봇과 서버에 동일한 값이 필요합니다. 파일·값을 채팅이나 GitHub에 올리지 마세요.
4. 이 변경의 `server/`를 기존 서버에, `web/`을 기존 웹사이트에 함께 배포합니다. 서버는 기존과 같이 worker·인스턴스 각각 1개입니다. 새 Render 서비스나 DB는 필요하지 않습니다. **디스코드 봇은 Render에 설치하지 않고 PC에서만 실행합니다.** 서버 코드와 환경 변수 설정 없이 로컬 봇만 켜면 웹 인증은 연결되지 않습니다.
5. 봇을 Discord 서버에 `bot`, `applications.commands` 범위로 초대합니다. 필요한 권한은 **채널 보기, 메시지 보내기, 메시지 기록 보기, 채널 관리**입니다. 전체 관리자 권한·메시지 내용 intent·서버 멤버 intent는 사용하지 않습니다. 관리자 계정 `481652220618604544`가 그 서버에 있어야 합니다.
6. `start-keybot.ps1`로 봇을 켜 둡니다. 기존 가상 환경을 사용하려면 `python -m pip install -r keybot/requirements.txt`, `python -m keybot.setup`, `python -m keybot` 순서로 실행해도 됩니다.

설정을 바꾸려면 `.venv-keybot/Scripts/python -m keybot.setup`을 실행합니다. 토큰 입력을 비우면 기존 값을 유지합니다. 봇을 두 개 동시에 실행하지 마세요. PC 종료·절전·인터넷 단절 시 새 웹 인증과 새 실행은 차단됩니다. 이미 접수된 작업은 서버에서 계속될 수 있고 시간제 작업은 설정된 만료 시각에 중지됩니다. 기존 접속의 중지·긴급 삭제는 인증 봇이 없어도 가능합니다.

## 관리자 명령어

모든 관리 명령은 Discord의 역할 이름이나 관리자 권한과 무관하게 **사용자 ID `481652220618604544`만** 실행할 수 있습니다. 다른 사람에게 주는 발급권은 지정된 조건의 키를 정해진 개수만 받는 권한이며, 새 발급권을 만드는 관리자 권한이 아닙니다.

| 명령 | 기능 / 예시 |
|---|---|
| `/문의패널` | 관리자와 요청자가 대화하는 비공개 티켓 채널 생성 버튼 |
| `/발급패널` | 미사용 발급권으로 키를 DM으로 받는 버튼 |
| `/다회용티켓지급 대상:@사용자 횟수:3 수량:1` | 실행 3회 키를 1개 발급할 권한 |
| `/시간제티켓지급 대상:@사용자 일수:3 수량:1` | 발급 후 3일간 사용할 키를 1개 발급할 권한 |
| `/기간티켓지급 대상:@사용자 기간:1달 수량:1` | 1일·3일·1주일·1달·1년·영구 중 선택 |
| `/발급권회수 대상:@사용자` | 아직 사용하지 않은 발급권 회수 |
| `/키폐기 발급번호:…` | DM에 적힌 발급 번호로 키의 다음 인증·실행 차단 |

관리자 본인도 자신에게 발급권을 지급한 후 발급 패널을 사용할 수 있습니다. 지급 명령의 `수량`은 발급할 **키의 개수**, `횟수`는 **키 하나당 실행 가능 횟수**입니다. 이용자가 발급 버튼을 누르면 해당 키가 그 이용자의 DM으로만 전달됩니다. 여러 종류의 발급권이 있으면 종류를 선택합니다. DM이 차단되면 발급권을 돌려주며 공개 채널로 키를 보내지 않습니다.

티켓 채널은 패널이 있는 카테고리에 생성하며 일반 멤버의 접근을 차단합니다. 동일 사용자의 기존 채널이 있으면 다시 안내합니다. 봇도 처리에 필요한 접근 권한을 가집니다. **Discord 서버 소유자와 Administrator 권한 보유자는 Discord 정책상 채널 제한을 우회하므로, 이들까지 숨기는 것은 불가능합니다.** [Discord 권한 문서](https://docs.discord.com/developers/topics/permissions)

## 이용자 흐름

1. `/발급패널`의 버튼으로 키를 DM으로 받습니다.
2. 웹사이트에 접속하면 바로 **키 입력 창**이 표시됩니다.
3. DM에서 받은 5자리 키를 입력하면 자체 백엔드가 검증하고 새 임의 세션 토큰을 발급합니다. 로그인에는 사용 횟수를 차감하지 않습니다.
4. 인증 후 실행 화면이 열립니다. 이후 요청에는 원본 키를 보내지 않습니다. 키를 아는 사람이 사용할 수 있으므로 키를 공유하지 마세요. 발급권 사용은 지급받은 Discord 계정으로 제한하지만, 웹 로그인은 키 소지 여부로 인증합니다.

같은 브라우저 탭에서는 새로고침해도 세션이 유지되며, 서버 재시작이나 접속 만료 시 키로 다시 인증합니다. **다시 인증**은 새 웹 세션을 만드므로 기존 세션의 긴급 삭제를 먼저 완료하세요. 디스코드 접속 번호 승인 방식은 제거했습니다.

## 차감·기한·장애 처리

- 키는 영문 대문자와 숫자를 모두 포함하는 무작위 5자리입니다. 영문 입력은 대소문자를 구분하지 않습니다. 기존 키와 중복되지 않으며, 서버 저장은 별도 비밀값을 사용하는 HMAC으로만 합니다.
- 다회용 키는 **실행 요청을 검증하고 새 작업을 접수하는 단계에서 1회 차감**합니다. 인증·새로고침·상태 조회·중지·긴급 삭제는 차감하지 않습니다. 잘못된 URL, 이미 진행 중인 작업, 다른 작업으로 인한 서버 사용 중 응답에는 차감하지 않습니다. 접수 후 게시판 권한 오류·전송 실패·사용자 중지에는 자동 환불하지 않습니다.
- 동시 클릭은 DB 트랜잭션으로 처리하고, 같은 실행 요청 번호는 다시 차감하거나 실행하지 않습니다. 네트워크 단절이 차감 직후 발생하면 접수 응답을 받지 못해도 1회가 차감될 수 있습니다. 이때 실행 상태를 확인하세요. 웹 UI는 실행 요청을 자동 재전송하지 않습니다.
- 시간은 **키 발급 시점부터 KST(UTC+9)**입니다. 1일은 24시간, 1주일은 7일입니다. 1달·1년은 달력 기준 같은 시각이며 없는 날짜는 해당 월 말일로 조정합니다. 발급권을 지급한 시점부터 차감하지 않습니다. PC 시계를 자동 동기화하세요.
- 시간 만료 시 새 실행을 차단하고 진행 중인 전송에 중지를 요청합니다. 이미 전송 중인 요청은 결과를 확인한 뒤 정리합니다. 영구 키는 관리자가 폐기할 때까지 유효합니다. 키 폐기는 다음 인증·실행부터 적용하며 이미 접수된 작업을 소급 취소하지 않습니다.
- 인증 실패를 포함한 시도는 IP별 10분에 5회, 전체 1분에 60회로 제한합니다. 제한은 백엔드와 로컬 DB에서 확인합니다. 로컬 DB에는 IP 원문 대신 서버 비밀값을 사용한 식별 해시를 기록합니다.
- 원본 키는 로컬 DB에도 저장하지 않으므로 분실한 키를 조회할 수 없습니다. 관리자에게 새 발급권을 요청하세요. DM 발송 중 프로세스가 종료되면 다음 시작 시 미완료 키를 폐기하고 발급권을 복구합니다. 이 경우 이미 받은 DM의 키가 작동하지 않을 수 있으므로 재발급하세요.

## 저장·자원 사용

`.local/keybot/`에 설정과 SQLite DB가 있습니다. **봇을 종료한 상태에서 폴더 전체를 비공개로 백업**하세요. DB와 `KEY_HASH_SECRET`을 함께 보존해야 기존 키가 유지됩니다. 다른 사람이 이 폴더를 읽지 못하도록 Windows 사용자 계정과 폴더 접근 권한을 관리하세요. Git에서는 `.local/`과 DB·가상 환경이 제외됩니다.

봇은 Discord Gateway 연결 1개와 기존 서버로 나가는 WSS 연결 1개를 사용합니다. 로컬 포트 개방이나 터널은 없습니다. 웹 서버에는 Discord 패키지·키 DB가 올라가지 않습니다. 로그인 때만 키 검증 요청을 보내고, 이후에는 서버 내부 발급 ID로 실행 승인을 확인합니다. 상태 조회 때는 봇 호출을 하지 않습니다. 접속 유지와 작은 인증 메시지의 비용은 남으므로 추가 CPU·RAM 사용이 0이라고 보장하지는 않습니다.

## 검증

`python -m pytest -q`로 발급 권한, 발급권 수령자, DM 실패, 동시 차감, 재시작 보존, 달력 기한, 인증 제한, 실제 ASGI WebSocket 키 검증과 세션 발급, 실행 차감·재시도, 오프라인 차단을 확인합니다. `python tests/ui_smoke.py`는 외부 통신을 모의 응답으로 대체해 인증 후 실행·중지·긴급 삭제와 모바일 레이아웃을 확인합니다.
