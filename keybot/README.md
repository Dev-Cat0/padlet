# 로컬 디스코드 키 봇 v2

## 업데이트 및 실행

1. 이전 봇 CMD 창에서 Ctrl+C로 종료합니다.
2. 업데이트 ZIP의 내용을 **기존 PadletKeyBot 폴더에 덮어씁니다**. 기존 `.local/keybot/config.json`은 삭제하지 않습니다. 업데이트 ZIP에는 config.json과 기존 키 DB가 들어 있지 않습니다.
3. `start-keybot.cmd`를 실행합니다. 처음 사용한다면 새 봇 토큰과 Discord 서버 ID를 입력합니다. 기존 토큰·서버 ID는 유지하고 새 서버 연결 설정만 적용합니다.
4. **백그라운드 실행 시작** 메시지 뒤에는 CMD 창을 닫아도 됩니다.
5. `status-keybot.cmd`로 상태를 확인하고, `stop-keybot.cmd`로 종료합니다. 오류 로그는 `.local/keybot/bot.log`입니다.

컴퓨터 종료·로그아웃 시 봇도 종료됩니다. 재부팅 후에는 start-keybot.cmd를 다시 실행합니다. PC가 절전 상태면 Discord 봇 응답은 멈추지만, 웹사이트 키 검증·사용 횟수 차감·시간 만료·사용 로그는 웹 서버에서 계속 작동합니다.

설정 변경은 `configure-keybot.cmd`입니다. 토큰은 화면에 표시되지 않습니다. 대화에 노출했던 토큰은 Discord Developer Portal에서 Reset Token 후 교체하세요. `.local` 폴더와 배포 ZIP에는 관리 자격 정보가 있으므로 공유하지 않습니다.

## Discord 권한 및 로그

초대 범위: `bot`, `applications.commands`.
권한: 채널 보기, 메시지 보내기, 메시지 기록 보기, 채널 관리, **웹후크 관리**.
관리자 ID: `481652220618604544`.
로그 채널 ID: `1562751204935602258`.

봇 시작 시 지정 채널에 `Padlet 이용권 로그` 웹훅을 생성하거나 재사용합니다. 연결 실패 시 권한을 수정한 뒤 `/로그설정`을 실행합니다. 서버가 이 웹훅으로 기록하므로 봇을 꺼도 로그 전송을 시도합니다. Discord가 Render의 요청을 제한하는 경우 기록은 DB에 보관하며, 봇이 켜져 있으면 로컬 봇도 같은 대기열을 처리합니다. 두 전송기는 기록을 잠시 예약한 뒤 처리해 중복 전송을 줄입니다. 로컬 봇은 30초 이내에 대기 로그를 확인하고 발급 시에는 즉시 확인합니다. 웹훅 URL은 관리자 연결로만 전달하며 사이트에 노출하지 않습니다.

기록: 발급권 지급, 키 DM 발급 완료, 인증, 실행 사용, 폐기·회수. 각 기록에는 지급 대상 Discord ID, 이용권 종류, 발급 번호가 있습니다. 다회용은 사용 후 잔여 횟수, 시간제는 기록 시점의 잔여 시간·분·초 및 UTC+9 만료 시각, 영구권은 영구로 표시됩니다. 키 원문은 기록하지 않습니다.

웹 로그인은 키 소지 여부로 인증합니다. 로그의 Discord 계정은 **그 키를 지급받은 계정**이며 실제 브라우저 사용자의 신원을 증명하지는 않습니다. 키를 공유하지 마세요.

로그는 DB의 대기열에 먼저 저장합니다. Discord 장애 시 재시도하며 기록 번호로 구분합니다. Discord가 수신한 뒤 응답이 끊기는 경우 동일 기록 번호가 중복 게시될 수 있습니다. 로그 장애 때문에 실행 차감이 취소되지는 않습니다.

## 명령어

- `/문의패널`: 비공개 문의 채널 버튼.
- `/발급패널`: 보유 발급권으로 키를 DM으로 받는 버튼.
- `/다회용티켓지급 대상:@유저 횟수:1 수량:1`: 실행 1회 키 하나를 받을 권한.
- `/시간제티켓지급 대상:@유저 일수:3 수량:1`: 발급부터 3일 이용.
- `/기간티켓지급`: 1일·3일·1주일·1달·1년·영구.
- `/키폐기 발급번호:…`: 키 폐기 및 진행 중 작업에 중지 요청.
- `/발급권회수 대상:@유저`: 미사용 발급권만 회수.
- `/로그설정`: 지정 로그 채널 연결 또는 복구.

관리 명령은 Discord 역할과 관계없이 관리자 사용자 ID만 사용할 수 있습니다. 관리자 본인도 본인에게 발급권을 지급한 뒤 발급 버튼으로 받습니다. `횟수`는 키 하나의 실행 가능 횟수, `수량`은 받을 키의 개수입니다. Discord 서버 소유자와 Administrator 권한 보유자는 문의 채널의 접근 제한을 우회할 수 있습니다.

## 실행 횟수와 기한

- **실행 버튼으로 새 작업이 접수될 때 1회 차감**합니다. 1회권은 실행→중지 이후 다시 실행할 수 없습니다. 인증·상태 조회·새로고침·중지·삭제는 차감하지 않습니다.
- 잘못된 입력이나 이미 진행 중이라 거절한 요청은 차감하지 않습니다. 접수 후 오류·사용자 중지에는 횟수를 돌려주지 않습니다.
- DB 트랜잭션으로 동시 요청의 초과 사용을 차단합니다. 동일 요청 재전송은 작업을 추가 실행하거나 다시 차감하지 않습니다.
- 웹사이트에 남은 횟수 또는 UTC+9 만료 시각을 표시합니다. 0회·만료이면 실행 버튼이 잠기며 직접 API를 호출해도 서버가 거부합니다.
- 기한은 키 발급 시점부터 KST 기준입니다. 하루는 24시간, 1달·1년은 달력 기준입니다. 없는 날짜는 그 달 말일로 조정합니다.
- 만료 시 진행 중 작업에 중지를 요청하고 새 게시 요청을 차단합니다. 만료 전에 이미 전송한 요청은 결과 확인까지 진행될 수 있습니다.

## 저장과 보안

키·발급권·차감·로그는 Firebase Cloud Firestore 저장소에 있습니다. 봇 PC에는 Discord 설정과 서버 관리 연결 자격 정보만 필요합니다. 구버전 로컬 키 DB는 더 이상 사용하지 않습니다. v2 전환 시 기존 키는 이전하지 않으며 기존 웹 세션도 종료됩니다.

무작위 영문·숫자 5자리 원문은 DM과 최초 웹 인증 요청에서만 사용합니다. DB에는 서버 전용 비밀값으로 계산한 HMAC만 저장합니다. 로그인 후에는 별도의 임의 세션 토큰을 사용하며 키는 브라우저 저장소에 저장하지 않습니다. **자신이 입력한 최초 인증 요청은 자신의 개발자 도구에서 볼 수 있습니다.** 다른 사람의 키 목록·관리 연결 비밀값은 웹에 보내지 않습니다.

관리 요청은 HTTPS와 HMAC 서명·시각 제한·일회용 요청 번호로 검증합니다. 브라우저에서 관리 API 호출은 차단합니다. 키 추측 시도는 IP 식별 해시 및 전역 제한을 DB에 기록하므로 재시작으로 초기화되지 않습니다. DB 장애 시 인증·새 실행을 허용하지 않습니다. 이미 인증한 접속의 중지·긴급 삭제는 계속 가능합니다.

## 서버 운영

웹 서버와 패들렛 전송은 기존 Render에 유지하고, DB만 Firebase Cloud Firestore를 사용합니다. 브라우저는 Firestore에 직접 접근하지 않습니다. `firestore.rules`는 클라이언트 읽기·쓰기를 모두 거부합니다.

기존 Render 웹 서비스의 비공개 환경 변수:
- `FIREBASE_PROJECT_ID`: Firebase 프로젝트 ID.
- `FIREBASE_SERVICE_ACCOUNT_JSON`: 해당 프로젝트 서비스 계정 JSON 전체. 서버에서만 사용합니다. 대안으로 Render Secret File과 `GOOGLE_APPLICATION_CREDENTIALS`를 사용해도 됩니다.
- `KEY_HASH_SECRET`: 키 해시용 서버 비밀값. 기존 키 사용 중에는 임의로 변경하지 않습니다.
- `KEY_ADMIN_SECRET`: 로컬 봇과 서버의 관리 API 서명 비밀값.
- `FIREBASE_DATABASE_ID`: 기본 DB를 사용하면 생략합니다.

Firestore Standard의 `(default)` DB를 생성하고 `firebase deploy --only firestore --project 프로젝트ID`로 규칙·인덱스를 배포합니다. 서비스 계정에는 해당 프로젝트의 Cloud Datastore User 역할만 부여합니다. JSON 비밀 키와 관리 비밀값은 Git·웹 자산에 넣지 않습니다. 서버 SDK는 보안 규칙 대신 IAM 권한으로 접근하므로 서비스 계정 권한도 제한해야 합니다.

로컬 봇의 `.local/keybot/connection.json`에는 SERVER_URL과 같은 KEY_ADMIN_SECRET을 설정합니다. Discord 봇 토큰은 Render에 넣지 않습니다. 구버전 `KEY_AGENT_SECRET`, `KEY_DATABASE_URL`은 사용하지 않습니다.

Render 임시 디스크에는 키 DB를 저장하지 않습니다. Discord 봇·Gateway도 Render에서 실행하지 않습니다. 로그 전송은 이벤트 발생 시 깨우고, 대기 중에는 60초 주기로 확인합니다. 실제 사용량에 따라 Firestore 할당량을 확인하세요. Firebase 설정 전에는 인증·새 실행이 차단됩니다.

검증: `firebase emulators:exec --only firestore --project demo-padlet-key-tests "python -m pytest -q"`, `python tests/ui_smoke.py`. GitHub CI도 공식 Firestore 에뮬레이터에서 동시 차감·재접속 후 잔여 횟수·브라우저 직접 접근 차단을 확인합니다.
